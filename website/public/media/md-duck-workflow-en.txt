108-second captioned walkthrough, without audio. Arranged from actual Mac beta.10 captures of an isolated demo library. The Codex request was entered, not submitted; file changes were saved in the demo library. Publishing is an example handoff: no live backend was connected and no article was published. Mac and Windows use the same file workflow, with different window appearance and shortcuts.

00:00:00  A space for each project.
Add a local folder as a space.

Keep drafts, series and bilingual reviews in separate places. Switch at the top right and resume reading.
Spaces point to your folders. They do not duplicate your articles.

00:00:09  A few drafts? Start here.
Put a few Markdown files in one folder and start reading.

Keep writing with your usual AI. With a chat-only tool, save the returned text yourself.
Reading local files requires neither an API key nor Codex.

00:00:18  Give a series an order.
One folder per series.
One subfolder per article.

Use 01-, 02- name prefixes and sort by name. Keep translations and images with each article.
The same folder structure works on Mac and Windows.

00:00:27  Make the request specific.
Copy a passage or capture it.

“Add product, size, quantity, delivery city and date. Use placeholders for unknown facts. Update both languages.”
Mac: ⌘ C / ⇧ ⌘ 4. Windows: Ctrl C / Win ⇧ S.

00:00:36  Give any AI the right file.
Copy Space instructions for AI. Add the passage or screenshot and your request.

An AI with file access saves in place. Otherwise, you save its returned text.
Instructions identify the folder and article; they do not grant access.

00:00:45  Or use local Codex.
Install and sign in to Codex CLI. Check the space, article and request, then start a local task.

Approve individual requests when asked. Stop or take over when needed.
Request entered, not submitted. External AI chats are not controlled.

00:00:54  Save. The reader updates.
The revised text stays in the original files.

In this isolated demo, saving the source and translation refreshed the article in MD Duck.
Switching reading spaces does not retarget a running Codex task.

00:01:03  Find and compare changes.
Filter to changed articles.
Choose View changes to compare with the last confirmed version.

Opening an article alone does not clear its marker.
An external file save is not proof that an AI task has finished.

00:01:12  Keep feedback beside it.
Leave a note on the passage.

Collect several comments for your AI to address. For bilingual articles, check the meaning and affected translation too.
Notes stay with the article. You decide what should be revised.

00:01:21  Reviewed? Mark as viewed.
After checking facts, wording and the translation, choose Mark as viewed. This revision’s marker clears.

New saved edits will appear for your next review.
This updates the comparison baseline. It does not approve publication.

00:01:30  Approve the publishing handoff.
Use your own CMS or an authorized AI to publish. Review its preview, then confirm publication.

Keep article.md, its translation and assets/ locally.
Publishing is an example handoff. No backend was connected or article published.

00:01:39  Archive. Return when needed.
Archive completed work in MD Duck, then restore it when it needs an update.

Move or back up the whole article folder, including hidden review data.
Download the examples and try the workflow at your own pace.

# 用 AI 定位 MD Duck 的文章空间

MD Duck 的一个空间对应一个本地文件夹。AI 或编辑器负责修改 Markdown，MD Duck 负责阅读与审阅保存后的文件。

右上角显示当前空间的图片预览和名称，点击即可直接切换。第一行放文章标题与空间，第二行放阅读模式、批注与工具。切换时显示目标空间，文件加载后淡入；系统开启减少动态效果时取消淡入。没有本地图片的空间使用纸张预览。

先在 MD Duck 添加文章文件夹，进入该空间，点击“交给 AI”。可以启动 Codex 本地任务，也可以打开“给其他 AI 的空间说明”，复制给你使用的 AI。其中包括本机的空间标识、绝对目录、当前文章相对路径和打开链接。外部 AI 能否读取或修改文件，仍取决于它自己的本地文件权限。

## Codex 本地任务

这项功能需要电脑上已经安装并登录 Codex CLI。它使用本机 Codex 的登录与额度，与阅读器中的 AI 翻译密钥分开。macOS 与 Windows 使用同一套任务流程；Windows 还需要 Codex 自身的沙箱已设置就绪。未安装、未登录或沙箱未就绪时，面板会说明原因，阅读功能仍可使用。

1. 进入目标空间，点击“交给 AI”。确认显示的工作目录；需要时带上当前文章。
2. 输入具体修改要求，主动提交后才开始。MD Duck 为这个空间启动独立 Codex 任务，不会接管其他已有对话。
3. 顶部持续显示真实任务状态。需要命令或文件审批时，面板显示请求，由你逐次批准或拒绝；提问也在面板中回答。
4. 切到其他空间阅读不会改变任务目录。任务执行期间，应用内的移动、归档和翻译会暂时阻止，避免同时改写文章；阅读与批注可以继续。
5. “我来接管”和“停止任务”都会中断这项任务，等待 Codex 确认后再显示已停止。已经保存的文件不会自动撤销。接管后可自行修改，或者输入下一条要求继续交给 AI。
6. 完成后显示“待你审阅”，可从“任务期间更新”列表返回文章。应用会核对任务前后的本地文件，覆盖 AI 用命令保存文章的情况；其他编辑器在同一期间保存的修改也可能计入。任务不会自动批准文章内容或发布到网站。

任务信息保存在本机应用数据目录。退出应用时中断由 MD Duck 启动的任务；重启不自动续跑。若进程意外断开，显示“连接中断，状态未知”，而不是声称任务已经停止。

普通文件监听不能识别是谁改了文章。其他编辑器或外部 AI 保存文件时，空间显示文件更新与待查看数量，不会冒充 Codex 运行状态。接管也不锁住其他软件的文件写入。

## 一次任务固定一个目标

- 用空间标识定位空间，用绝对目录核对文件。名称只用于辨认，可以重名或改名。
- 任务开始后固定空间与目标文件。用户切换到另一个阅读空间，不会改变这次 AI 任务的目标。
- 沿用现有文件组织：`article.md` 与 `article.zh.md` 配对，图片放在文章旁的 `assets/`，用相对路径引用。普通单语 Markdown 也可直接阅读。
- 保留已有 `<!-- block:... -->` 标记；不改 `.review/`、`.mdduck/`、批注、词汇记录或应用设置。
- 保存后报告实际修改路径与内容，再打开下面的链接让用户复核。定位操作不会自动批准文章、完成批注或发布内容。
- 无法访问本地目录时，应明确说明并提供可手动保存的内容，不能声称已修改文件。

## 打开空间或某篇文章

从界面复制实际链接最可靠。下面的 UUID 是示例，必须替换为这台电脑上的空间标识。

```text
mdduck://open?space=a67367f1-af92-4f73-b735-dc9e854ef065
mdduck://open?space=a67367f1-af92-4f73-b735-dc9e854ef065&path=01-series%2Farticle.md
```

`path` 可省略，省略时恢复该空间上次阅读的文章；提供时必须是空间内部的 Markdown 相对路径。通过 URL 传递时，应使用 URL 编码，不手动拼接未经编码的空格、`&`、`#` 等字符。

已安装版本注册 `mdduck://` 链接。空间已经打开时聚焦它的窗口；没有打开时为该空间打开窗口，保留其他空间的阅读状态。无效标识、找不到的文章、绝对路径、`..` 越界路径或指向空间外部的符号链接都会被拒绝，不会转而操作当前空间。

macOS 终端：

```sh
open 'mdduck://open?space=a67367f1-af92-4f73-b735-dc9e854ef065&path=01-series%2Farticle.md'
```

Windows PowerShell：

```powershell
Start-Process 'mdduck://open?space=a67367f1-af92-4f73-b735-dc9e854ef065&path=01-series%2Farticle.md'
```

若系统未注册链接、使用便携版或存在多个旧安装副本，使用明确的应用可执行文件路径和 CLI 参数。以下安装位置也只是示例，请替换成实际路径；这样可以避免启动错误版本。

macOS：

```sh
"/Applications/MD Duck.app/Contents/MacOS/MD Duck" \
  --mdduck-space a67367f1-af92-4f73-b735-dc9e854ef065 \
  --mdduck-file '01-series/article.md'
```

Windows PowerShell：

```powershell
& 'C:\实际安装目录\MD Duck.exe' `
  --mdduck-space a67367f1-af92-4f73-b735-dc9e854ef065 `
  --mdduck-file '01-series/article.md'
```

CLI 的 `--mdduck-file` 同样可省略；提供文件时必须同时提供 `--mdduck-space`。CLI 相对路径不需要 URL 编码，带空格时用引号包住。Windows 的 `\` 分隔符也可识别，说明和 Markdown 图片路径统一推荐 `/`。

## 本机数据与跨设备

空间标识属于本机 MD Duck 配置，不是云端账号或公开地址。把链接发给另一台电脑，并不会同步文章、注册空间或授予权限。另一台 Mac 或 Windows 电脑应先拥有对应文件夹，在 MD Duck 添加它，再复制该机器自己的空间说明。路径与空间标识不能直接照搬。

第一次使用空间功能时，旧配置会备份为应用数据目录中的 `settings.pre-spaces.json`，原设置文件保留；原文章文件夹成为第一个空间，设置和阅读位置复制到该空间配置。批注和译文仍保存在原有位置。移除空间只移除快捷入口，保留文章与该空间的阅读数据；重新添加同一目录会恢复原空间标识与配置。目录搬动后使用“重新定位文件夹”关联新位置。

源码开发运行与安装应用是两种入口：开发环境默认不注册系统 `mdduck://` 链接。对源码构建进行验证时，应使用项目自身的 Electron 运行入口、明确的参数及隔离测试配置，不把仓库路径当成安装版可执行文件，也不要用真实资料库替代测试数据。

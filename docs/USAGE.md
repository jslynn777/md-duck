# 从 AI 初稿到定稿：用 MD Duck 认真读一遍

[English](USAGE.en.md) · [Mac / Windows 分步演示](https://mdduck.com/guide/#quickstart) · [复制 AI 提示词](https://mdduck.com/guide/#ai-workflow)

用自己熟悉的 AI 写文章，保存到本地，在 MD Duck 中认真读。发现某一段写得含糊，就截图或复制文字给 AI，说明怎么改；文件保存后，回来读修改后的结果。满意后，再用自己的发布工具，或让有后台权限的 AI 发布，本地继续保留文章。

MD Duck 负责阅读和审阅，不编辑文章正文，也不连接网站后台发布。双语对照、批注、查词和朗读按需使用。这个写作流程不要求在 MD Duck 中配置 AI 密钥，也不限定某一家 AI。

## 第一次使用：从一篇文章开始

1. 在电脑上建一个「文章库」文件夹，或使用已有的 Markdown 文件夹。
2. 放入一篇 `article.md`。需要中文对照时，在同一目录放入 `article.zh.md`。
3. 在 MD Duck 的「文件 → 打开文件夹」中选择文章库，点击左侧文章开始读。没有现成文章可先「打开示例」，或解压[起步示例包](https://mdduck.com/examples/md-duck-starter.zip)后打开它的文件夹。
4. 读到不满意的段落，选中文字复制，或用系统截图工具截取这一段，发到自己的 AI 对话框。附上文章位置和具体要求，例如「这一步只写了等待片刻，请补充判断方法；其他段落不动」。
5. 让 AI 修改原文件，或把它给出的完整内容保存回本地。回到 MD Duck 重读修改处；有双语稿时再检查对应内容。
6. 确认文章满意后，让有授权的 AI 或你自己准备后台草稿，检查发布预览后再上线。本地文章和图片继续保留。

你也可以只打开一份普通 Markdown。系列目录、中文稿和块标记都是按需使用。想集中记下多处问题时，再用批注：选中文字 →「批注」→ 保存，随后从批注面板复制意见给 AI；修改后由你复核并标记完成。

## 按需要组织文件，不必一开始就分类

几篇文章可以直接散放在文章库中；文章多了，再按系列建文件夹。MD Duck 读取你已经整理好的目录，不会自动分类，也不要求每一篇都套用同一种结构。

| 你现在要做的事 | 文件怎么放、怎么用 |
| --- | --- |
| 临时读一份稿子 | 直接「打开文件」，无需先建立文章库。 |
| 阅读几篇零散文章 | 将 `ideas.md`、`meeting-notes.md` 等放在同一个文件夹，打开该文件夹即可。 |
| 一次写十几篇系列文章 | 建 `01-家庭咖啡指南/` 等系列目录，按 `01-`、`02-` 命名文章文件或子文件夹，让顺序可见。 |
| 文章有图片或中文对照 | 建独立文章目录，放 `article.md`、可选的 `article.zh.md` 和 `assets/`，整理时一起移动。 |
| 只想改其中一段 | 截图或复制那段交给 AI，说明只改这一处；保存原文件后继续读，不必重建文章。 |
| 系列完成，暂时不再读 | 在文章或目录菜单中归档，保留文件和关联审阅记录，需要时恢复。 |

带系列、译文和图片的文章可以这样放：

```text
文章库/
  01-产品选购系列/
    01-如何选择/
      article.md
      article.zh.md
      assets/
        detail.png
    02-准备资料/
      article.md
      article.zh.md
  02-使用与维护系列/
    01-日常维护/
      article.md
```

- **有素材或译文时，推荐一篇文章一个子文件夹。** 原稿、译文和素材能一起整理，也方便一次让 AI 写十几篇。纯文字文章直接放在系列目录下也可以。
- **序号放在文件夹名中。** 侧栏默认按名称自然排序，例如 `02-` 在 `10-` 前。独立 `article.md` 文章按所在文章文件夹名排序；显示的标题可以不带序号。
- **排序入口在侧栏。** 可切换名称正序、名称倒序、文章标题或手动顺序。手动顺序下用文章菜单中的「上移／下移」整理；切换排序不改文件名或正文。
- **普通文件名也可用。** `notes.md` 对应 `notes.zh.md`；`notes.markdown` 对应 `notes.zh.markdown`。已有文件不用批量改名。单语稿不需要空白中文文件。
- **图片放在文章内。** 写成 `![细节说明](assets/detail.png)`，图片要真实存在。Markdown 内统一使用 `/`，Mac 与 Windows 都可读。

文件保存为 UTF-8。Windows 请在资源管理器中显示文件扩展名，确认不是 `article.md.txt`。给文件夹起名时避免 `<>:"/\|?*`、结尾空格/句点以及 `CON` 等 Windows 保留名；中文名字可以使用。

## 让任何 AI 按同一套规则交稿

在程序的「使用指南」或官网指南中，复制「写作提示词」。先补上主题、读者、篇数、目标文件夹和语言要求，再发给你正在使用的 AI。

**能读写本地文件的 AI**：给它指定文章库的准确位置，让它在其中创建或修改文件。要求完成后报告真实保存路径和检查结果。

**网页聊天中的 AI**：它不一定能访问你的电脑。让它按「文件名＋完整代码块」输出，再由你保存成对应文件；不要把整段聊天记录保存成文章。已有文章需要修改时，提供最新全文，以及截图或摘录和修改要求；截图能指出问题，不能代替完整源文件。

**只改当前这一段**：从官网指南复制「截图／摘录修改提示词」，附上截图或原文、文章位置和期望结果。例如：「这一段只说适量和等待片刻。请把家庭冲煮的操作写得可执行，说明用量和判断依据，保持原来的语气，只修改这段。」AI 应在最新文件中确认位置，保留其他内容和原块 ID。文字不清或位置不唯一时，先补充原文给它。

**一次处理多处问题**：使用「批注修改提示词」，在占位处粘贴批注面板导出的意见。意见包含引用和可用的定位信息；AI 按最新文件定位、只改相关内容。批注方便留待下一轮处理，并不是修改文章的必经步骤。

**确认后再发布**：使用官网的「发布交接提示词」，补充本地定稿位置、目标网站、栏目，以及新建还是更新已有文章。让有权限的 AI 先准备内容或后台草稿并给出预览，等你确认本次发布再上线，最后打开公开页面核对并返回实际网址。没有后台权限时，由它交付可发布内容，再由你手动发布。MD Duck 不会代你完成这些后台操作。

## 中文对照怎样稳定对应

文件名把两份稿子关联起来，块标记负责精确对应内容。每个标题、段落、图片、整张表格、引用块或代码块前使用一个标记，前后各空一行：

`article.md`：

```markdown
<!-- block:intro -->

Read one section at a time.
```

`article.zh.md`：

```markdown
<!-- block:intro -->

一次读一个小节。
```

ID 只能用英文字母、数字、连字符或下划线，例如 `intro`、`step-01`。同一份文件内不能重复；原文和译文使用相同的 ID、顺序和块结构。**修改已有段落保留 ID，新增内容才增加 ID。**

每个顶层列表项分别标记：

```markdown
- <!-- block:check-source --> Check the source.
- <!-- block:check-detail --> Add one useful detail.
```

译文也使用两个对应列表项；整张表格用一个标记，并保持两侧行列数相同。不要只在列表前放一个标记，就以为所有项目都有对应关系。

打开双语对照后点「检查整篇」，按问题位置返回编辑器修改。检查只读，不会自动配对或重写文件；没有标记的两份稿子也能并排阅读。配对通过只表示结构对应，含义与翻译仍由你审阅。

## 最顺手的日常流程

1. **先确定系列目录。** 让 AI 先列出每篇要回答的问题，避免十篇都在重复同一个主题。需要时用「＋ → 批量新建文章」准备目录，再让 AI 填正文。
2. **把写作工具和 MD Duck 并排。** 一边改文件，一边读实际阅读效果。外部保存会自动反映，不用重新导入。
3. **一次审一个小节。** 先看逻辑和事实，再看措辞。直接截图或复制一段给 AI，把要求写成具体动作，例如「补充适用尺寸和计算例子」。想读完整篇再集中修改时，把问题留成批注。
4. **按需要选择阅读方式。** `1` 看英文、`2` 看中文、`3` 看对照；「阅读排版」调字号。朗读和查词可以辅助核对，AI 解释与翻译是可选功能。
5. **一轮修改，一轮复核。** AI 保存后，回到 MD Duck 重新阅读改过的段落。有双语稿时检查另一侧；使用过批注时，复核「待复核」意见并手动确认。AI 的「已修改」是交付说明，内容仍由你验收。
6. **发布后留存。** 确认定稿，再在自己的后台发布，或交给有权限的 AI 执行。核对线上结果，本地保留定稿和素材；暂时不用的系列可归档，之后从「已归档」恢复。若需保留初稿和每一轮修改，在改写前另存副本或使用版本管理。

## 找到 AI 刚改过的文章

1. 原文或译文保存了不同内容，侧栏文章会显示「有改动」，文件夹也会显示数量。点击「有改动」可筛选当前「全部」或「已归档」列表，仍保留原有排序。
2. 打开文章，点「查看改动」，对照上次确认与现在的内容；用上一处、下一处查看，也可定位到正文。
3. 读完后点「标为已查看」，将现在的内容作为下一轮比较起点。仅打开文章不会清除标记，也不会替你完成批注。

首次记录文章时只建立比较起点，不提示已有内容是改动。比较记录保存在本地，只保留最近一次确认的版本；它不能代替保存每轮修改的版本管理。

## Mac 与 Windows 操作对照

| 操作 | Mac | Windows |
| --- | --- | --- |
| 打开文章库 | `⌘ O` | `Ctrl O` |
| 打开单个文件 | `⇧ ⌘ O` | `Ctrl Shift O` |
| 复制选中的原文 | `⌘ C` | `Ctrl C` |
| 截取一段画面 | `⇧ ⌘ 4` | `Win Shift S` |
| 粘贴到 AI 对话框 | `⌘ V` | `Ctrl V` |
| 保存正在编辑的批注 | `⌘ Enter` | `Ctrl Enter` |
| 打开设置 | `⌘ ,` | `Ctrl ,` |
| 选中文字后新建批注 | `Option Enter` | `Alt Enter` |
| 系统文件管理器 | Finder | 文件资源管理器 |
| 文章管理菜单 | 右键，或文章旁的「…」 | 右键，或文章旁的「…」 |

两套系统使用相同的文章、译文和块标记规则。Mac 的 `⌘` 对应这里的 Windows `Ctrl`，`Option` 对应 `Alt`；`1 / 2 / 3`、`B` 和 `Esc` 等阅读快捷键在未输入文字时使用。

Mac 截图默认保存为文件，可拖入 AI 对话框；截图时再按住 `Control` 可复制到剪贴板。Windows 截图后可直接粘贴。图片输入仍取决于你所用的 AI 是否支持；不支持时复制文字即可。

## 整理与备份

程序内的重命名、移动和归档直接作用于本地文件。需要整理时优先使用文章或文件夹的「…」，独立文章目录会连同译文、素材及关联记录一起处理。目标重名时不会覆盖；引用目录外共享素材的文章，应按提示整理包含素材的完整目录。

外部整理时也尽量移动完整文件夹；无法确认文章身份时，先按程序提示检查。不要为了清理而删除隐藏的 `.review/` 或 `.mdduck/`。

备份或换电脑时复制**整个文章库，包括隐藏目录**。`.review/` 保存审阅与词汇等数据，`.mdduck/` 保存文章库管理信息和改动比较记录。应用设置、阅读位置、未保存批注草稿和 AI 配置另存在当前电脑，单独复制文章库不会带走这些本机资料；换电脑前先保存批注草稿，新电脑按需重新设置。

安装包和平台要求见[下载页面](https://mdduck.com/download/)，常见问题及联网说明见[完整指南](https://mdduck.com/guide/)。

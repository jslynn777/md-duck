# Source-pinned English phoneme engine

MD Duck uses the phoneme-only ephone / eSpeak NG fork by Sergii Mykoliuk at commit 4f6d246c1d3acf67a4d814e20da02fa3967bc92d. Its complete source archive retains the original engine and per-file copyright headers, English dictionary/rule inputs, Unicode database/tools, and upstream build recipes. No precompiled phonemizer npm worker is used.

SOURCE.json records the exact source archive, official Emscripten 3.1.64 build image digest, complete Emscripten source archive, generated byte hashes, US/UK language selection, and three build-recipe adaptations. Engine C/C++ files are unmodified. The generated ephone.js contains its own WebAssembly bytes and bundled JavaScript runtime; lang/en_all.js contains generated English data.

COPYING and COPYING.UCD-TOOLS are the upstream GPL v3 text, COPYING.UNICODE is the Unicode database text. COPYING.EMSCRIPTEN, COPYING.MUSL, COPYING.COMPILER-RT, COPYING.LIBCXX, COPYING.LIBCXXABI and COPYING.LIBUNWIND retain the exact runtime and compiler-library notices from the pinned Emscripten source. Component and per-file headers remain in the delivered full source archives; these texts do not relicense them.

From the corresponding MD Duck source root, with Node.js and Docker installed:

    node scripts/build-phonemizer.mjs --archive third-party/source-archives/ephone-js-4f6d246.tar.gz --verify

Omitting --verify regenerates the same committed engine and language files only after checking their exact byte hashes. On Windows, run this maintainer-only command in WSL2 with Docker and Node.js; ordinary users require neither. The fixed compiler image includes the native dictionary compiler and LLVM tools; the delivered Emscripten archive includes the runtime C/C++ sources linked into WebAssembly. The container requires no app profile, credentials or model cache.

Kokoro normalization invokes this engine for en-US/en. The adapter removes only the engine-added terminal full stop; the original Kokoro normalizer preserves source punctuation. Five real neural voice tests matched the prior released Kokoro implementation sample-for-sample. The offline packaging checks independently exercise the compiled phoneme engine and both English data variants.
